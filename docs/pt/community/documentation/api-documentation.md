# Documentação da API

Todas as APIs devem ser documentadas em RAML ou Swagger, consulte Architecture-Documentation-Guidelines\]\(Architecture-Documentation-Guidelines.md\)



**Títulos de secção**

* Não numere os títulos — por exemplo, "Prepare and Fulfill", e não "C - Prepare and Fulfill"
* Certifique-se de que os títulos de secção \(\# \) correspondem ao título respetivo no PDF completo \(gerado a partir do [ficheiro de configuração do dactyl](https://github.com/Mojaloop/Docs/blob/master/ExportDocs/dactyl-config.yml)\)
* Não inclua a palavra "documentação" nos títulos

#### Facilidade de localização

* Para secções que contenham muitas subsecções de endpoints ou métodos, forneça um índice no início da secção
* Não diga a palavra projeto; use componente, microserviço, interfaces, etc.

#### Linguagem

Em vez da palavra "projeto", use um substantivo específico, tal como componente, microserviço ou interface.

#### Procedimentos

* Introduza os procedimentos com títulos H3 \(\#\#\#\) ou H4 \(\#\#\#\#\) \(não H2 \(\#\#\)\).
* Não use números nos títulos das secções de procedimentos.
* Use marcação de lista ordenada para os passos dos procedimentos. Por exemplo:
* Passo 1
* Passo 2
* Passo 3
