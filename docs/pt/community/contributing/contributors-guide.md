# Guia do contribuidor

Estamos satisfeitos por estar a considerar tornar-se parte da comunidade Mojaloop.

_Nota: Se usa, ou planeia usar, ferramentas de Inteligência Artificial (IA) como parte do seu fluxo de trabalho de contribuição para o Mojaloop,
certifique-se de que leu integralmente e cumpre a nossa [política de uso responsável de IA](../standards/ai_policy.md)._

Com base na fase atual do projeto Mojaloop, procuramos os seguintes tipos de contribuidores:

## Tipos de contribuidores

- #### Contribuidores individuais

Estas pessoas são as que querem começar a contribuir para a comunidade Mojaloop. Pode tratar-se de um
desenvolvedor de software ou de um profissional de garantia de qualidade que queira escrever código novo ou corrigir um bug. Pode também ser um especialista de negócio,
de conformidade ou de risco que queira ajudar a fornecer regras, escrever documentação ou participar na recolha
de requisitos.

- #### Operadores de hub

Tipicamente, são organizações, indivíduos ou agências governamentais interessados em montar o seu próprio
Switch Mojaloop para passar a fazer parte do ecossistema.

- #### Equipas de implementação

As equipas de implementação podem ajudar bancos, serviços governamentais, operadores móveis ou cooperativas de crédito a fazer o deployment do Mojaloop.

## Como contribuo?

* Leia e familiarize-se com os nossos [processos de engenharia de produto](./product-engineering-process.md)
  e com os [processos de revisão de desenho e de código do Mojaloop](./design-review.md).
* Consulte o [Guia de deployment do Mojaloop](https://docs.mojaloop.io/documentation/deployment-guide/) e
  o [Guia de onboarding](https://github.com/mojaloop/mojaloop/blob/master/onboarding.md).
* Percorra a [Visão geral dos repositórios](https://docs.mojaloop.io/documentation/repositories/) para compreender como o
  código do Mojaloop é gerido em múltiplos repositórios Github.
* Familiarize-se com as nossas [Normas](../standards/guide.md) para contribuir para este projeto.
* Percorra a [Lista de verificação para novos contribuidores](./new-contributor-checklist.md), navegue pelo quadro do projeto e
  trabalhe no
  seu [good first issue](https://github.com/mojaloop/project/issues?q=is%3Aopen+is%3Aissue+label%3A%22good+first+issue%22)
* Consulte o [Roadmap](../mojaloop-roadmap.md) e contribua para oportunidades futuras.
* Familiarize-se com o [Código de conduta](./code-of-conduct.md) da nossa Comunidade.

## Que trabalho é necessário?

O Mojaloop segue um [processo de engenharia de produto](./product-engineering-process.md) estruturado e mantemos ativamente
um [roadmap](../mojaloop-roadmap.md) dos desenvolvimentos de novas funcionalidades e do trabalho de manutenção. Pode encontrar informação sobre os nossos
workstreams oficiais atualmente em curso na
nossa [página de workstreams no community central](https://community.mojaloop.io/pi-24-workstreams).

Cada workstream do Mojaloop mantém um backlog de itens de trabalho no GitHub e um workspace no ZenHub; contacte o
líder do workstream ou publique uma mensagem no canal slack do workstream para se apresentar e encontrar um bom ticket para começar a trabalhar.
Encontrará os contactos dos líderes dos workstreams e a informação sobre os canais slack na
nossa [página de workstreams no community central](https://community.mojaloop.io/pi-24-workstreams).

## O que está aqui e o que não está?

Este é código livre, disponibilizado sob uma [licença Apache 2.0](https://github.com/mojaloop/mojaloop/blob/master/LICENSE.md).

O código é lançado com uma licença Apache 2.0, mas os documentos de Especificação sob os documentos 'mojaloop-specification'
são publicados com a licença CC BY-ND 4.0

Não fornecemos servidores de produção para o correr. Isso é da sua responsabilidade. É livre \(e encorajado!\) de clonar estes
repositórios, participar na comunidade de desenvolvedores e contribuir de volta para o código.

Não estamos a tentar substituir carteiras móveis ou prestadores de serviços financeiros. Fornecemos uma plataforma para ligar entre si novos
e existentes
prestadores financeiros, usando um scheme comum. Existem serviços centrais para identificar o prestador de um cliente, cotação,
fulfillment, liquidação líquida diferida e gestão de fraude partilhada. Cada prestador pode aproveitar estes serviços para
enviar e receber dinheiro de outros no sistema, e não tem qualquer custo para fazer o onboarding de novos prestadores. Fornecemos código
para um exemplo simples de prestador de mobile money, para mostrar como a integração pode ser feita, mas o nosso DFSP de exemplo não pretende ser
um prestador de mobile money de produção.
